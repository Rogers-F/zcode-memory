# ZCode Memory Unified for DSH

保留 DSH 原生设置页、只读文件预览、工具注册及权限链，事实修改经统一核心的 journal、互斥、冲突和可恢复归档。DSH 插件仍要求 Node >=24 / DSH 0.2.1-rc.2，不能用 Node 22 的核心兼容性替代宿主要求。

The versioned Release `zcode-memory-dsh-0.3.0.tgz` includes the full runtime. Import/install it through the native plugin manager; use its plugin switch to enable/disable, import the next package with the same name to update while retaining configuration, and Remove/Uninstall without selecting data deletion. Cordis activation/disposal owns native tools and listeners; disabling the plugin removes those effects until it is re-enabled. Memory and settings live outside the installed code and survive replacement/removal. The native Cordis lifecycle is tested; the browser installer/update UI is still an explicit verification boundary.

On unload, the adapter also retires its last synthetic memory attachment from each active session's visible surface and cancels pending recall. Removing the hook alone would leave AgentLoop's previous request override visible. User/assistant/tool history and the native immutable audit log remain; the next model request has no plugin attachment or memory rules.

Its package name is `@local/zcode-memory-dsh`; Cordis configuration namespace is `zcode-memory-unified`. Both `enabled` and `extractionEnabled` default to false. Enabling the workspace viewer does not enable automatic model inference. Explicitly enable extraction in native plugin configuration or with the memory_settings tool. Settings, source provenance, usage, recall budgets and revisions are available through the native memory tools. Data stays in the separate DSH home subdirectory `zcode-memory-unified`.

Run standard tests/build/pack from the unified project root. Installed DSH public runtime packages are tested using an isolated HOME, native AgentLoop and scripted provider. No real account, credentials or profile is used. Native Read/Write/Edit, read-only policy, Chinese extraction and cold-session injection have been exercised; the actual browser GUI and remote clients remain unverified. Every pre-step replaces the prior temporary attachment with a bounded index plus the session's still-valid selected bodies. A real tool call / second model step and later user turn keep this working set; forget/revisions remove stale entries. No durable once-only injection receipts are used. Compaction clears the working set and the next pre-step rebuilds it. Repeated queries reuse selection/body caches; index and bodies share request/session budgets. Optional unbash is not bundled offline; without it the POSIX classification path fails closed, while native file tools continue working. Local storage does not mean local inference: enabled extraction sends relevant context to the selected DSH provider and can cost tokens. See root README and retained notices.

The retained browser settings/viewer bundle is version-controlled at `assets/client-runtime.cjs`, with its original notices and marked license. The root build places those exact bytes at the exported `dist/client.js`; fresh Git checkouts do not depend on ignored local build output. Client-source changes require an explicit DSH client rebuild/review of that resource before release.

Optional semanticRecallEnabled defaults to false, independent from extractionEnabled. It reuses the selected DSH model through shared structured model.recall, with one request per query, timeout/cancellation and local BM25 fallback. Native memory_settings can also opt in. Index and bodies share one budget; completed-turn extraction excludes synthetic/tool/summary messages. This may transmit queries and candidate summaries and incur model fees. See the root README for coverage and output budget limits.
